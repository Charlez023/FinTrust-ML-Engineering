# FinTrust ML Engineering — Initial Implementation Plan

## Week 2 — Analyse and Prepare

In Week 2, the main focus will be understanding the datasets better and preparing them for machine learning work. I will also review the modelling outputs from the Data Science track when they are available so the MLE work can connect properly with the model.

I will inspect and validate the customer and transaction datasets and set up the Python environment for the project. I will also start building the data-loading and validation components so the data can be checked before moving to the next stages.

The preprocessing pipeline will also be started during this week. This will include handling missing values, converting data into the required formats, and preparing the structure of the features that will be used by the model. I will also begin writing automated tests for the components being developed.

By the end of Week 2, I expect to have a working Python environment, a basic data-loading component, initial validation checks, an initial preprocessing pipeline, and basic automated tests.

## Week 3 — Develop and Integrate

Week 3 will focus on connecting the main ML components. Once the model from the Data Science track is available, I will connect it to the preprocessing workflow and work on the inference process.

The trained model should be saved and loaded properly so that it can be reused without training it again for every prediction. If an API is needed for the project, I will also begin working on a simple service that can receive input data and return predictions.

I will connect the ML component with relevant parts of the other project tracks and test how the different components work together.

By the end of Week 3, I expect to have an integrated ML pipeline, an inference component, a model saving and loading process, and an initial API or service if it is required. Integration tests will also be added.

## Week 4 — Test, Refine and Present

Week 4 will focus on testing the complete workflow and fixing problems that are found. I will test how data moves through validation, preprocessing, the model, and inference.

I will also check how the system handles different inputs and look for problems when the different components are connected. The project setup will be reviewed to make sure another person can understand and run the workflow using the documentation.

The technical documentation will be updated with the work completed, including important assumptions and limitations. I will then prepare the technical evidence and presentation materials for the final project review.

By the end of Week 4, I expect to have a tested end-to-end workflow, improved technical components, updated documentation, testing evidence, and final presentation materials.
